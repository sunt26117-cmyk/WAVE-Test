# WAVE-Test 第四轮深度审查与修复记录

## 1. 本轮审查重点

本轮以第三轮修复源码为基线，继续检查 MOS Thermal、FOC DynoLab、网页 TypeScript 与离线 Python/Streamlit 导出实现之间的一致性。审查不把单元测试通过等同于真实硬件模型已验证。

## 2. 本轮新增修复

### 2.1 MOS Thermal / FOC 六管热仿真

1. **修正动态导通损耗参考口径**
   - 不再用平均结温下的单点 Rds 温度系数，反推整个非稳态波形的 25°C 导通损耗。
   - 改为逐样本累计 25°C 参考导通损耗，再由热反馈/温度相关模型处理工作温度影响。
   - 这样避免电流平方与结温随时间相关时，使用平均温度近似造成偏差。

2. **拆分“热安全”与“指定电流可实现性”**
   - 堵转热扫描增加 `thermalSafeAtRequestedCurrent`，单独表达请求电流下的热结果。
   - 总体 `steadySafe` 不再只因温度暂时未越限就给出安全结论；电压条件不可实现、稳态不收敛等情况会阻止 SAFE。
   - 对电压受限的请求电流明确标注：热结果仅是强制该电流下的条件估算，不代表系统实际可达到该电流。

3. **修正低电流 RMS 平方地板**
   - 相电流 RMS 平方使用 `Ipk²/2`，移除固定 `1e-9` 下限，避免极小电流工况产生非物理的虚假导通损耗。

4. **保留历史边界保护**
   - 结温读取使用 Cauer 网络结侧节点，不把内部热节点最高温度直接当作 Tj。
   - 标量 Board 温度不再虚构六颗 MOS 的初始结温。
   - 用户指定的短时堵转时域不再被自动扩展到至少 5 秒。

### 2.2 FOC DynoLab 参数辨识

1. **自动 Ke 不再用带载点替代空载反电势**
   - 自动 Ke 至少要求两个有效空载候选点。
   - 空载证据不足时，保留工程基准 Ke/n0，并给出降级警告，不再拿最高带载转速伪装空载转速。

2. **P0(n) 拟合增加可辨识性检查**
   - 模型为 `P0(n)=a·|n|+b·n²`，约束 `a>=0`、`b>=0`。
   - 除样本数量、不同转速档数和速度跨度外，新增归一化设计矩阵条件数检查，条件数必须 `<=40`。
   - 条件数过大时视为参数病态、不可可靠区分，保留基础 P0 参数并明确告警，不把不稳定系数冒充标定结果。
   - `40` 是当前软件的保守数值门槛，不是适用于所有电机和测量噪声的普适物理常数。

3. **扩展功率单位识别与拒绝边界**
   - 明确支持 W、mW、kW、MW、GW、TW，并保持 `MW` 与 `mW` 的大小写语义。
   - 明确拒绝 hp/horsepower、PS、VA/kVA/MVA、dBm，以及 Wh/kWh 等能量单位作为功率输入。
   - 不允许未知显式单位静默按 W 处理。

### 2.3 TypeScript 网页版与 Python/Streamlit 版一致性

本轮发现此前两端虽然输入相同，但可能得到不同的 Ke/P0/β/Rs 和误差报告。这是实质性产品缺陷，不只是代码风格差异。

1. **P0 拟合器统一**
   - TypeScript 使用非负约束解析最小二乘：先检查双参数无约束解，若落在非负域外，则比较两个单参数边界解和零解。
   - Python 之前使用 SciPy `least_squares`，有额外系数上限和不同迭代路径。
   - 现已将 Python 改成与 TypeScript 相同的解析非负最小二乘实现，移除这条标定路径对 `least_squares` 的依赖。

2. **β/Rs 搜索器统一**
   - Python 之前使用 SciPy 有界迭代，与浏览器的网格搜索及局部细化不同。
   - 现统一为相同的 β 网格、Rs 网格、边界和局部细化步骤，确保相同数据能得到一致参数。

3. **修复留出验证数据泄漏**
   - 旧 Python 验证流程使用全量闭环拟合结果评估留出集，训练/验证边界不干净。
   - 现按与浏览器一致的分组方式划分训练与留出数据；β/Rs 仅由训练集重新拟合。
   - Ke/P0 不从闭环留出点回流：Ke 依据独立开环空载证据，P0 优先来自独立开环数据；证据不足时退回基准 P0，不用验证点补拟合。
   - 留出点若无法完成物理解算则跳过，不再把该点当成零扭矩误差计入 MAE；同时报告总留出点数、有效扭矩验证点数和有效效率验证点数。

4. **修正无效物理解算的数据表达**
   - 无法物理解算的闭环点用 NaN 表达，不再伪装成 0 扭矩、0 损耗或零误差。
   - MAE/RMSE/MAPE 只基于有效点；没有有效点时为 NaN。
   - 参数灵敏度指标也排除无法物理解算的点。
   - Python 空闭环数据时状态统一为 `failed`，指标返回 NaN；锁定 Rs 模式也显式输出最终有效 Rs，避免参数结构与网页端不同。

## 4. 未完成 / 不能宣称完成的事项

1. **完整项目类型检查与构建未完成**：当前执行环境没有安装项目真实依赖；本轮没有完成 `npm run lint` / `npm run build`。语法扫描 0 错误不能代替 `tsc`。
2. **Excel 真实依赖集成未验证**：当前缺少真实 `xlsx` 依赖，不能宣称真实 Excel 文件解析已通过集成测试。
3. **独立 HTML 尚未重新构建**：项目内现存 `index.html` 仍是之前构建的产物；本轮源码修复需要在完整依赖环境运行 `npm ci`、`npm run build` 后才能进入离线 HTML。
4. **MOS 损耗模型仍需器件实测标定**：Eon/Eoff、Qrr、Eoss 的真实电压/电流/温度/栅极电阻依赖，仍需要对应 MOS 数据手册曲线或 DPT 数据验证。当前软件侧的输入口径保护不能代替 DPT。
5. **热网络仍需硬件验证**：六管互热、PCB 空间热扩散、铜层/过孔/焊盘及外壳边界条件，最终需要 PCB 结构信息、热测试或经校核的 3D 热仿真来确认。
6. **FOC 模型需要台架数据确认适用范围**：Ke、Rs、Lq、磁饱和、弱磁及四象限功率平衡的最终精度，需要电机台架数据、接法信息（Y/Δ）、电流/电压测量定义和温度条件支撑。

## 5. 建议下一轮重点

1. MOS Thermal：把 Eon/Eoff、Qrr、Eoss 作为电压/电流/温度/驱动条件的 LUT 或插值模型，检查重复计入、能量符号及每周期/每器件口径。
