# WAVE-Test 第三轮深挖与修复记录

## 1. 本轮结论

第三轮重点审查 MOS Thermal、FOC DynoLab、Scope 桥接和 AC 耦合数据处理。修复集中在：非均匀时间轴的物理量计算、模型数据与测量数据来源区分、六管损耗模型输入口径说明，以及无效 Duty/时间轴拒绝策略。

本轮相关回归覆盖 3 个测试文件，共 **44/44 通过**；68 个 TypeScript/TSX 文件语法扫描 **0 错误**；针对 `scopeBridge.ts`、`uiController.ts` 及其依赖的定向 TypeScript 类型检查通过。完整项目 `npm run lint` 和生产构建没有完成，具体限制见第 5 节。

## 2. 已修复问题

### 2.1 FOC DynoLab → Scope 的非均匀时间轴元数据矛盾

**原问题**：批量日志生成 Scope Tab 时，`fs/dt` 由全段平均间隔计算，而 `SamplingMetadata` 的采样率按中位间隔计算。时间戳非均匀时，通道元数据和质量审计会给出两种不同的采样基准；依赖 `channel.fs/dt` 的频率或周期功能可能失真。

**修复**：统一以 `analyzeSamplingQuality()` 得到的 robust median `dt` 作为名义间隔，`fs=1/dt`；实际时间数组仍保持原始时间戳，不重采样、不等间隔化。

**新增保护**：批量日志及六管合成波形导出前，必须满足时间戳有限且严格递增；NaN、重复、倒退时间戳直接拒绝生成 Scope Tab。

### 2.2 每个通道的无效样本计数串扰

**原问题**：同一 Tab 的多个通道共享同一个 `SamplingMetadata` 对象，且元数据中的 `signalNanCount` 来自时间轴分析，无法反映各通道自身 NaN/Inf 数量。一个通道的无效值可能被错误归因到其它通道，或者所有通道都显示 0。

**修复**：每个 `WaveformChannel` 获得独立 metadata 副本，`signalNanCount` 按该通道的幅值数组单独统计，并复制 `gapIndices`，避免对象共享造成后续修改串扰。

### 2.3 缺失合成 Duty 被伪造成 50%

**原问题**：合成波形声明包含 Duty 后，如果某个采样点的 `da/db/dc` 缺失，桥接代码以 `0.5` 静默补齐。这会把缺失数据伪装成真实的中点占空比，并可能进入 MOS 损耗分析。

**修复**：只要 `includeDuty=true`，所有样本的三相 Duty 都必须存在、有限且位于 `[0,1]`；任何一项不满足就拒绝导出，不再补造 50%。

### 2.4 测量通道与模型反算通道来源混淆

**原问题**：DynoLab 批量日志转 Scope 时，`Iq_est/Vq_motor/Vq_cmd/m_cmd` 是由物理模型反算或计算的估算值，但原数据来源类型没有 `derived_estimate`，容易与实测波形混为一类。

**修复**：新增 `derived_estimate` 来源类型。

- `Ibus_filt`、`Vbus_meas` 标记为 `measured`，来源模型字段为 `dynolab_runtime_log_input`。
- `Iq_est`、`Vq_motor`、`Vq_cmd`、`m_cmd` 标记为 `derived_estimate`，来源模型字段为 `foc_inverse_steady_state_model`。
- 六 MOS 合成通道仍保留 `synthetic_steady_state` 和生成模型名。

示波器文件摘要新增 Primary source / Model 信息，避免仅凭通道名称判断来源。扭矩纹波分析仍只把来源确认为 `measured` 的转矩通道视为实测轴端转矩。

### 2.5 非均匀采样的 AC 耦合偏置均值错误

**原问题**：`computeChannelMean()` 对所有波形按样本数算术平均。非均匀采样时，采样密集区权重过大、采样稀疏区权重过小。该函数不仅用于绘图，还用于 FOC Thermal、热损耗、Scope 数据桥接等模块的 AC 耦合偏置去除，可能改变电流直流偏置和损耗输入。

**修复**：当通道元数据判定为非均匀采样且时间轴与幅值长度一致时，改用相邻有效样本的梯形积分计算时间加权平均值；时间轴非法或无法积分时退回旧的有限值样本平均策略。均匀采样仍沿用原来的有界快速均值路径。

新增回归：`t=[0,1,9,10]`、`v=[0,10,10,0]`，按样本均值会得到 5 V，按实际时间梯形积分得到 9 V；验证结果为 9 V。

### 2.6 MOS Thermal 的 DPT 能量输入口径说明不足

**原问题**：六管模型把 `Eon+Eoff` 解释为单颗硬开关器件每 PWM 周期的能量，并按电流方向分配到对应硬开关器件；若用户导入的是整桥或半桥合计值，可能发生损耗重复计算或漏算。Eoss 当前按 `(Vbus/Vref)^2` 缩放，隐含假设等效 Coss 不随电压变化，而实际 MOS 的 Coss/Eoss 通常具有明显非线性。

**修复**：在仿真警告中明确：

- `Eon+Eoff` 的输入口径必须是“单颗硬开关 MOS、每 PWM 周期”；整桥/半桥合计值必须先换算。
- 当启用 Eoss 时，明确提示当前是单点 Eoss + `V²` 近似；需要用器件 `Eoss(V)` / `Qoss(V)` 曲线或多工况 DPT/LUT 替代，当前结果只能作为近似估算。

本轮没有擅自修改 Eoss/Eon 的物理公式，因为缺少具体器件数据手册曲线和 DPT 工况；避免把未经验证的拟合公式伪装成更精确模型。

### 2.7 Math Parser 在非严格 TS 配置下的联合类型收窄

**原问题**：当前 TS 配置未启用 `strictNullChecks` 时，布尔判别联合类型的末端返回可能残留 `number | Float32Array` 类型，定向类型检查失败。

**修复**：在已提前返回标量分支后，对剩余结果明确声明为 `Float32Array`。没有改变运行时数据。

## 4. 仍然存在的模型边界（不是本轮已解决项）

1. **MOS 开关损耗**：仍以标量缩放或可用 DPT/LUT 为基础；缺少具体 MOS 在 Vbus、Id、Tj、Rg 多维工况的完整损耗表时，不能作为最坏开关损耗签核依据。
2. **Eoss**：当前单点 Eoss 按 V² 近似；真实 Coss 非线性需要 Eoss(V)/Qoss(V) 曲线或测量数据。
3. **六管热网络空间效应**：当前六个器件支路汇入单一共享 Board 节点的集总模型；没有 PCB 铜厚、铜箔、过孔、布局与六管互热阻矩阵，无法代表真实 PCB 空间温度场。
4. **合成波形模型**：DynoLab 的理想正弦电流/周期平均 Duty 不包含 PWM 载波、实际开关纹波、ADC 采样窗口及真实死区畸变，不能代替示波器实测开关波形。
5. **FOC DynoLab 适用范围**：现有模型说明假定 Y 型接法、非凸极 SPMSM、`Id=0`。Delta 接法、IPMSM 凸极转矩、高速弱磁 `Id<0` 和动态 `dI/dt` 不能直接套用当前参数反算公式。
6. **电机绕组参数换算**：`R_LL/2` 与 `L_LL/2` 的相参数锚定依赖 Y 型接法假设；当前没有显式星形/三角形配置。输入线间数据前必须确认接法及测量方法。
7. **AC 非均匀采样偏置均值**：梯形积分是按相邻样本分段线性变化的时间平均近似；如果采样缺口中包含未捕获窄脉冲，任何均值估计都无法恢复缺失事件，仍需结合原始波形采集质量判断。
